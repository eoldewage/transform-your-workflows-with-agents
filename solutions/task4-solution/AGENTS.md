Use MATLAB for MATLAB work.
Keep changes small.
All tasks should be completed in less than 5 minutes.
Prioritize readability and understandability over robustness.
Don't explore folders adjacent to the project root folder.
When generalizing a workflow, model the user's core concepts rather than
preserving incidental roles from the original example.
Test both the default workflow and representative alternative configurations,
including combinations that use different source formats or data types.
Use Git for project version control. Create a local commit after every
verified change. Do not push or modify remote repositories without explicit
user permission.
Follow red-green-refactor test-driven development. Create or update the
targeted test first, verify its failing red state before changing behavior,
then implement the smallest change to reach green. Run the targeted test
before the whole applicable suite, and run that suite before committing.
