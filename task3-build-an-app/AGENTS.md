Use MATLAB for MATLAB work.
Keep changes small.
Prefer short, clear names for grouping structs and use their fields directly instead of unpacking fields into local aliases.
Follow proper test-driven development principles for behavior changes: write or update a targeted test first and observe the red state, implement the smallest change to reach green, then run the targeted test again before running the whole suite.
Use the local git repository for version control. Commit after each verified change. Do not push, pull, add remotes, or change remote configuration without explicit user permission.
